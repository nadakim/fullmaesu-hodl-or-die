# 장 마감 정산 (Settlement)

> MASTER_PLAN S1. 곱하기 콘텐츠(S4)·정산 연출(S6)·유물 슬롯(S2)의 토대. 2026-09-27 도입.

## 왜

전에는 돈이 주가 변동에서만 나왔고, 유물 보너스는 평가손익에 %p를 더해 한 번 곱하는 방식(`relicAdjustedPnl`)이었다. 그래서 유물을 많이 모아도 1.5배 수준에서 멈췄다.
이제 유물 효과는 **장 마감마다 실제 현금 보너스**가 된다. 다음 날엔 더 큰 원금으로 베팅할 수 있으므로 복리 눈덩이가 된다. 배수(`mult`·`xmult`) 구조라서 S4의 곱하기 유물·카드가 그대로 얹힌다.

## 규칙

장 마감(`endOfDay`) 맨 처음에 `settleDay()`를 부른다. 이자·존버 나무·보유일 증가보다 먼저 한다.

포지션마다 다음 순서로 계산한다.

```
base   = 직전 장 마감(또는 매수) 이후 가격 손익 = dir × (노출액 − refExp)     ← 레버리지·롱/숏 반영, 밤사이 갭 포함
chips  = base + Σ add                (칩 더하기, 발라트로의 칩)
mult   = (1 + Σ mult) × Π xmult      (합산 배수 · 곱 배수, 발라트로의 배수)
정산금 = chips × mult − base          (base는 이미 평가손익에 들어 있다 → 보너스분만 현금)
```

- **수익(base > 0)** 이면 `onLoss: false` 효과만 적용한다. **손실(base < 0)** 이면 손실을 줄이는 `onLoss: true` 효과만 적용한다. 예: 국밥 정신 `xmult ×0.5`는 손실의 절반을 환급한다. base가 0이면 정산이 없다.
- 효과는 **`run.relics` 순서대로** 발동한다. S2에서 이 순서가 슬롯 순서가 된다. 순서는 합·곱 결과를 바꾸지 않고, 단계별 몫(연출·체인 금액)만 바꾼다.
- `refExp` = 정산 기준 노출액이다. 매수할 때 = 진입 노출액, 추가 매수할 때 += 새 몫, 부분 매도할 때 ×(1−비율), 디레버리지할 때 = 남은 수량 비율만큼, 정산 뒤에 = 지금 노출액. 평단을 바꾸는 카드(존버는 승리한다·복리의 마법)는 `entryExposure`·원금만 바꾸고 `refExp`는 건드리지 않는다. 그래서 카드로 만든 평가손익 변화는 정산 base에 들어가지 않는다.
- 장중에 판 포지션은 정산하지 않는다. 장 마감까지 들고 있어야 받는다.
- 평가손익·증거금률·청산·순자산은 **순수 가격 손익**(`rawPnl`)이다. 유물 보정이 두 번 들어가지 않게 평가손익 쪽 보정을 없앴다.

## 기존 유물 이관

| 유물 | 전 (평가손익 보정) | 후 (정산) |
|---|---|---|
| 🍲 국밥 정신 | 방어주·우량주 평가손실 −50% (반대매매 계산에도) | 그날 손실로 마감하면 손실의 50% 환급 (`xmult ×0.5`, onLoss). 장중 반대매매 방어 효과는 사라진다 |
| 🔏 존버의 인장 | 장 마감 3번 이상 넘긴 포지션 평가이익 ×1.2 | 같은 조건으로 그날 수익 `xmult ×1.2`. 판정 시점은 오늘 보유일이 늘기 전 |
| 🔥 테마주 헌터 | 테마주·동전주 평가이익 ×1.15 | 그날 수익 `xmult ×1.15` |
| 📈 떡상 적금 | 스택당 평가이익 +1%p (합산) | 스택당 `mult +0.01` |
| 🩹 반대매매 생존자 | 스택당 레버리지·숏 평가이익 +3%p (합산) | 스택당 `mult +0.03` |

식은 전과 같다: mult = (1 + 떡상 + 생존자) × 인장 × 테마. 달라진 점은 **적용 대상이 누적 평가이익에서 그날 수익**으로 바뀌었다는 것, 그리고 보너스가 **현금으로 확정**된다는 것이다.

## 기록 (연출·UI는 재생만)

- `run.lastDay = { round, day, payout, settlement: [{ posId, posName, assetId, dir, lev, base, steps, chips, mult, payout, sources }] }` → `emit('daySettled', run.lastDay)`
  - `steps` = `[{ label, kind: 'base'|'add'|'mult'|'xmult', value, runningChips, runningMult, source }]` (S6 정산 연출이 이 순서대로 재생)
  - `sources` = 단계별 보너스 몫 `[{ source, label, amount }]`, 합 = payout
- 누적: `run.settledToday`, `run.settledTotal`, `run.maxSettleMult`(이번 판 하루 최대 배수), `run.maxSettlePayout`, 이번 주 `run.weekDays`
- 주간 결산 체인 `buildSettlementChain`: 이번 주 정산 기록을 포지션별·유물별로 합친 요약이다. base = 이번 주 장 마감 손익, add = 유물별 보너스 합 + 💎 다이아몬드. `run.lastWeek.settled` = 이번 주 보너스 합. 주 마지막 날에는 유물 발동 연출(`relicTriggered`)을 내지 않는다. 체인이 대신 보여 준다.

## 예상 정산 미리보기

- `previewSettlement(extra)`: 순수 함수로, rand를 쓰지 않고 상태도 바꾸지 않는다. 포지션별 배수 = `settleSteps(p, 1).mult`(오늘 수익이 났을 때의 배수)이다.
  전체 배수 = **노출액 가중 평균**이다. 모든 포지션이 유리하게 1% 움직일 때 받는 돈 ÷ 기본 손익으로 구한다. 포지션별 `per1pct` = 유리하게 +1%일 때 정산 후 손익이다.
- `hypotheticalBuy(stockId)`: 종목 카드를 쓰면 생길 포지션이다(대기 중인 신용·영끌·공매도 반영). 카드 툴팁에 "쓰면 정산 배수 ×a → ×b"로 나온다.
- 화면: 행동력 줄의 `정산 ×1.26` 칩이다. 오르면 숫자가 튀고, 호버하면 포지션별 배수와 +1% 예시가 나온다. 큰 연출은 S6에서 넣는다.
- 손패 격자 카드 EV(HANDOFF Open Q4)의 대안이다. 대상 카드·S4 곱하기 카드의 미리보기는 해당 단계에서 `SETTLE_EFFECTS`와 함께 넓힌다.

## 큰 수 표시 (`formatKrw`, UI 유틸)

- 게임 금액 단위는 **만 원**이다. 단위: 만·억·조·경·해·자·양·구·간·정·재·극·항하사·아승기·나유타·불가사의·무량대수(10⁶⁸원).
- 상위 두 단위까지 표시한다. 1억 원 미만은 정확히("2,345만"), 1조 원 미만은 두 단위 그대로("1,234억 5,678만"), **1조 원 이상은 유효숫자 4자리 반올림**("3조 2,420억")이다. 무량대수를 넘으면 원 단위 지수 표기("1.2e+72")를 쓴다.
- **정밀도 결정**: 금액은 JS Number 그대로 두고 `BigInt`는 쓰지 않는다. 시뮬레이터와 C# 이식이 복잡해지기 때문이다. Number는 2⁵³ ≈ 9×10¹⁵까지 정수가 정확하다. 단위가 만 원이므로 정확한 범위는 약 9경 원이다. 그 이상(10²⁰, 해 단위 이상)에서는 덧셈 정밀도가 의미 없어지지만, 표시가 유효숫자 4자리라서 드러나지 않는다. Number 최댓값(약 1.8×10³⁰⁸)은 무량대수보다 훨씬 크다.
- `fmtMoney`·`fmtSigned`·`fmtSlush`·`fmtTipMoney`·`fmtEv`가 전부 `formatKrw`를 거친다.
