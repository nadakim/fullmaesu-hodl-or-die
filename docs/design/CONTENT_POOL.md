# CONTENT POOL — 콘텐츠 확장 후보 목록

> 2026-09-28 기획. 현재 카드 75장·유물 35개(해금 전 기준) → **출시 목표 카드 110장 안팎·유물 80개 안팎 + 카드 도장 4종**.
> Claude Code는 이 목록을 **배치(10개 안팎) 단위**로 구현한다. 한 배치 = 한 PR. 아래 §0 규칙을 지킨다.

## §0. 구현 규칙

1. **중복 확인 먼저.** 이미 있는 카드·유물(이름이 달라도 효과가 같으면 중복)은 건너뛰고 목록에 "중복 — 기존 ○○"로 표시한다.
2. **효과는 기존 훅으로.** 정산 배수는 `SETTLE_EFFECTS` 한 줄, 행동력은 `cardCost`, 드로우는 `drawCards`, 찌라시는 `tipChances`, 이자는 `dailyInterest`, 암시장은 `shopPrice`·`serviceCost` 등 이미 있는 계산 지점에서 `hasRelic()` 분기. 새 훅이 꼭 필요하면 PR 설명에 이유를 적는다.
3. **수치는 전부 CONFIG 상수.** 아래 표의 수치는 **초안**이다. 시뮬 결과를 보고 조정안을 제시하되, 사용자 승인 없이 크게 바꾸지 않는다.
4. **문구는 한국 주식·코인 커뮤니티 밈 톤.** 금지 소재(자살 연상, 실존 기업명·티커·실존 인물)는 절대 쓰지 않는다. 이름이 걸리면 바꾸고 보고.
5. **각 항목에 필수 필드:** 등급, 태그(`TAGS` 7종 중), 해금 여부(시작부터 열림 / 해금 조건 — `UNLOCKS.md` 규칙), 플레이버 한 줄.
6. **검증:** 배치마다 `node sim/runner.js` baseline 비교 + 새 유물·카드별 "보유/사용 시 클리어율·최고 순자산 변화" 표. 한 개만으로 클리어율 +20%p 이상이면 과한 것으로 보고. `tools/tests` 통과, 도감 스크린샷.
7. **좋은 유물의 조건** (발라트로 조커 설계 원칙): ① 한 줄로 이해된다 ② 플레이어의 선택을 바꾼다(어떤 종목·카드·배치를 고르게 만든다) ③ 다른 유물과 조합될 여지가 있다. 셋 중 ②가 없으면 탈락.

## §1. 설계 분류 (발라트로 조커 분류를 이 게임에 옮긴 것)

| 분류 | 역할 | 비율 목표 |
|---|---|---|
| A. 더하기 | 초반 안정감. 칩(+) 또는 합산 배수(+) | 20% |
| B. 조건부 곱하기 | "이 조건을 맞추면 ×" — 플레이 방식을 바꾼다 | 25% |
| C. 성장형 | 판이 진행될수록 커진다. 초기화 조건으로 긴장 | 15% |

| E. 규칙 비틀기 | 행동력·드로우·손패·레버리지 한도 등 게임 규칙 자체를 바꿈 | 10% |

| G. 복사·재발동·운 | 다른 유물을 증폭 | 5% |

## §4. 카드 도장 (발라트로의 강화·에디션 — 적은 공수로 조합 수를 크게 늘림)

카드 한 장에 도장 하나를 찍는다. 같은 카드라도 도장에 따라 가치가 달라진다.

| 도장 | 효과 초안 | 얻는 곳 |
|---|---|---|
| 🥇 금박 | 사용할 때 비자금 +30 | 암시장 서비스·팩 |
| ✨ 홀로 | 사용한 날 정산 합산 배수 +0.5 | 암시장 서비스·팩 |
| 🌈 프리즘 | 사용한 날 정산 ×1.3 | 희귀 팩·보스 보상 |
| 🔴 빨간 도장 | 효과가 한 번 더 발동 | 전설 팩·보스 보상 |

- 엔진: 카드 인스턴스에 `stamp` 필드. `newCard`·저장·강화·복제에서 보존. 정산 효과는 `SETTLE_EFFECTS`처럼 도장 효과 표 한 곳.
- 화면: 카드 테두리 반짝임·아이콘. 도감에 도장 설명.
- 암시장 서비스 `shopService('stamp', deckIdx)` 추가(비용 `serviceCost`).

## §5. 배치 계획
