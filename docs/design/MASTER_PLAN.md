## §0. 작업 규칙 (모든 단계 공통 — 어기지 말 것)

1. **CLAUDE.md 규칙이 우선이다.** 엔진은 DOM 금지·`emit()`만, 수치는 CONFIG, 엔진 난수는 `rand()`, UI 연출 난수는 `Math.random`. 빌드 도구·npm 의존성·외부 라이브러리 금지. 금지 소재(한강·다리·투신·수온 등 자살 연상, 실존 기업명·티커) 금지.
2. **한 단계 = 한 브랜치 = 한 PR.** 최신 `main`에서 `claude/<단계이름>` 브랜치를 만들고, 단계 안의 작업은 항목별로 커밋한다. 단계가 끝나면 PR을 올리고 **사용자 승인 전에는 다음 단계로 넘어가지 않는다.**
3. **작업 종류별 검증**
   - UI·연출만 바꾼 작업: `engine.js` 무변경, `node sim/runner.js` 결과 JSON 전후 **완전히 동일**.
   - 엔진 규칙을 바꾼 작업: 변경 전 `sim/results/baseline-before-<작업>.json` 저장 → 변경 후 같은 시드로 실행 → 전략별 클리어율·평균 생존 주차·파산 원인 변화를 **표로 보고**.
   - UI를 바꾼 작업: 1920×1080, 1366×768, 1280×800(스팀덱) 스크린샷 + `tools/tests/` 회귀 테스트 통과.
4. **수치 조정은 "조정안만".** 밸런스 수치(목표 금액, 확률, 배수 상한 등)는 시뮬레이터 결과를 보고 **조정안을 제시만** 하고 바꾸지 않는다. 사용자가 고른다.
5. **🛑 표시가 있는 곳은 멈춘다.** 사용자의 결정이 필요한 지점이다. 선택지와 추천안을 정리해서 PR 설명과 채팅에 올리고 기다린다. 그 단계의 나머지 작업은 진행해도 된다.
6. **게임 텍스트**는 한국 주식·코인 커뮤니티 밈 톤 ("영끌", "존버", "풀매수", "리딩방 찌라시"). 카드 설명 문구를 임의로 고치지 말고, 잘리면 목록만 보고.
7. **설계 문서**: 새 시스템은 `docs/design/<이름>.md`에 규칙·수치를 정리하고, `docs/design/CHANGELOG.md`에 날짜·변경·이유를 한 줄씩 남긴다.
8. **HANDOFF.md** 를 세션 끝마다 갱신한다 (다음 세션이 이어받을 수 있게).

## §1. 이 계획의 목표 (왜 하는가)

> "놀랄 만큼 쉽고, 믿기 힘들 만큼 재밌고, 미쳐버린 배수로 중독되는 덱빌딩 로그라이크."

- **발라트로·클로버핏처럼 고점이 끝없이 높아야 한다.** 곱하기 시너지가 연쇄로 발동해서 조 → 경 → 해 → 자 단위까지 번다.
- **매일(하루 한 사이클마다) 쾌감이 터져야 한다.** 장 마감 정산이 하루의 메인 이벤트.
- **연출은 재미를 키울 뿐 만들지 못한다.** 그래서 순서는 반드시 **① 곱하기 구조(엔진) → ② 덱빌딩 도구 → ③ 연출** 이다.

현재 구조가 이 목표에 못 가는 이유 (반드시 이해하고 시작할 것):
1. 돈이 주가 변동에서만 나온다 → 원금 × 변동률 × 레버리지라 수억~수십억에서 멈춘다.
2. 유물 보너스가 전부 **더하기**다 (`relicAdjustedPnl`이 %p 합산 후 한 번 곱함) → 많이 모아도 1.5배 수준.
3. 성장형 유물에 폭주 방지 장치가 들어가 있다 (이 계획에서 **의도적으로 푼다**, §3-6).

### S1. 정산 스코어링 엔진 (가장 중요 — 모든 것의 토대)

**(1) 장 마감 정산.** 지금 결산 체인(`buildSettlementSteps`)은 "보여주기용 기록"이다. 이것을 **실제로 돈을 만드는 계산**으로 바꾼다.

- 새 엔진 함수 `settleDay()`를 `endOfDay()` 안에서 호출한다. 포지션마다:
  ```
  base      = 오늘 이 포지션의 평가손익 변화 (오늘 시가 대비 종가, 롱/숏·레버리지 반영). 음수면 정산 없음(손실은 그대로 반영).
  chips     = base + Σ(더하기 효과)                     ← 발라트로의 칩
  mult      = (1 + Σ 합산 배수) × Π(곱하기 배수들)       ← 발라트로의 배수
  정산금    = chips × mult − base   (이미 평가손익에 들어간 base는 빼고 "보너스분"만 현금 지급)
  ```
- 정산 보너스는 **현금으로 지급**(`run.cash += 정산금`)하고 `run.settledToday`·`run.settledTotal`에 누적. 다음 날 더 큰 원금으로 베팅 가능 → 복리 눈덩이.
- 적용 순서: 포지션 → (유물은 S2에서 슬롯 순서대로, S1에서는 기존 `run.relics` 배열 순서) → 카드 효과 → 크리티컬(S4).
- 각 단계는 `{label, kind:'base'|'add'|'mult'|'xmult', value, runningChips, runningMult, source}`로 기록해서 `run.lastDay.settlement = [{posId, steps, payout}]`와 `emit('daySettled', ...)`로 알린다. **정산 연출(S6)은 이 기록을 그대로 재생**한다.
- 기존 유물 보정(국밥 정신·존버의 인장·테마주 헌터 등)을 이 파이프라인으로 옮긴다: 지금 %p 합산 효과는 `add`(합산 배수)로, 곱으로 바꾸기로 한 것은 `xmult`로. **기존 `relicAdjustedPnl`의 평가손익 보정은 제거하고 정산으로 일원화**한다 (같은 효과가 두 번 적용되면 안 됨). 반대매매·증거금률 계산은 순수 평가손익 기준으로 단순해진다.
- 주간 결산 체인(`buildSettlementSteps`, `roundClear` 연출)은 "이번 주 5일 정산 합계" 요약으로 바꾸거나, 매일 정산으로 대체되면 제거. 🛑 어느 쪽인지 사용자에게 추천안(→ 매일 정산이 메인, 주간은 요약 한 화면)과 함께 확인.
- **목표 금액(ROUND_TARGETS)은 바꾸지 않는다.** 정산 도입 후 클리어율이 크게 오를 것 — 표로 보고하고 조정안만 제시 🛑.

**(2) 예상 정산 미리보기.** 장전에 화면에 "오늘 예상 배수 ×24"를 표시한다.
- 순수 함수 `previewSettlement()` (rand 금지, 상태 변경 금지): 현재 포지션·유물·대기 효과로 **배수(mult)** 를 계산. 금액은 주가에 달렸으니 배수만 보여주고, 포지션별 "오늘 +1%면 ₩얼마" 예시를 툴팁으로.
- 카드를 쓸 때마다 갱신, 배수가 오르면 숫자가 튀는 UI(연출은 S6에서 키움. 지금은 숫자 갱신 + 간단한 펀치만).
- HANDOFF Open Q4(격자 카드 EV)의 대안이 된다: 카드에 마우스를 올리면 "이 카드를 쓰면 배수 ×24 → ×36" 미리보기.

**(3) 한국 큰 수 단위 표시 (9).** 순수 함수 `formatKrw(n)` 하나로 통일 (엔진 아닌 UI 유틸):
- 만·억·조·경·해·자·양·구·간·정·재·극·항하사·아승기·나유타·불가사의·무량대수(10⁶⁸).
- 표기: 상위 두 단위까지 ("3조 2,400억", "12경 800조"). 무량대수 초과는 지수 표기 `1.2e+72`.
- **금액 변수의 정밀도**: JS Number는 2⁵³(약 9천조)를 넘으면 원 단위 정수가 깨진다. 게임 금액 단위가 이미 "만원"이므로 표현 한계는 넓지만, 10²⁰(해) 이상에서는 덧셈 정밀도가 무의미해진다. → 금액은 Number 그대로 두되 `formatKrw`가 유효숫자 3~4자리로 반올림 표기. `BigInt`는 쓰지 않는다(시뮬·C# 이식 복잡도). 이 결정을 `docs/design/SETTLEMENT.md`에 기록.
- 화면의 모든 금액 표시(`fmt` 계열 함수)를 `formatKrw`로 바꾼다. grep으로 누락 확인.

**검증:** 엔진 변경 → baseline 비교 표. 추가로 시뮬레이터에 "하루 최대 정산 배수", "판당 최고 순자산 분포(중앙값·상위 10%·최대)" 지표 추가. 문서 `docs/design/SETTLEMENT.md`.

### S7. 시장·종목 개편 (엔진 변경 — baseline 비교 필수)

- **(14) 레버리지별 반대매매 기준 현실화.** 사용자 원안("2배는 증거금 50% 이하, 3배는 33% 이하")은 **매수 직후 증거금률이 정확히 그 값이라 즉시 반대매매**가 되므로 그대로 쓰지 않는다. 대신 한국 신용거래의 **담보유지비율** 방식: `담보비율 = 포지션 평가액 ÷ 빌린 돈`, 이 값이 `MAINTENANCE_RATIO = 1.4`(140%) 미만이면 반대매매. 결과적으로 2배는 약 −30%, 3배는 약 −7% 하락에서 반대매매 → 3배가 훨씬 위험하다는 게 체감된다. 숏(대차)은 별도 기준 `SHORT_MAINTENANCE_RATIO`. 콜드월렛 유물은 기준 완화로 재정의. 🛑 수치는 시뮬 결과 보고 후 사용자 확정. (사용자 원안의 취지 = "레버리지가 높을수록 반대매매가 빨리 온다"는 이 방식으로 충족됨을 PR에 설명)
- **(15) 하루마다 차트 새로 시작.** 개장 때 캔들 영역 초기화, 전일 종가에서 시작, 전일 종가 기준선(점선) 표시. 과거 일봉은 큰 차트(22)의 "일봉" 탭으로.
- **(16) 지수 계산** 🛑: 현재는 지수가 먼저 움직이고 종목이 베타로 따라감. 선택지 — A) 유지(단순, 시장 카드 설계 그대로) / B) 종목 시가총액 가중평균으로 지수 산출(현실적, 대신 강세장·약세장 카드를 "전 종목 드리프트 부여"로 재설계). 추천: **A 유지 + 지수 툴팁에 "시장 전체 흐름(종목이 이걸 베타만큼 따라감)" 설명**. 사용자가 B를 고르면 별도 PR.

- **(18) 종목 이름**: 실제 업종을 떠올리게 하되 **실존 기업명·티커를 흉내 낸 이름은 금지**(CLAUDE.md). 기획 대화의 "카톡뱅크·테슬러·빛코인"은 실존 브랜드와 너무 가까워 **쓰지 않는다**. 대신 업종 + 밈 조합으로 새로 짓고 🛑 후보 20개를 사용자에게 제시. 예시 방향: 반도체전자(기존 유지), 전기차모터스, 떡상바이오, 김치코인, 존버건설, 흑우증권, 치킨게임즈, 상폐직전테크.

- `BOSSES` 데이터 + `bossMod(key, default)` 헬퍼 하나로 수정자 조회 (if문 흩뿌리기 금지).
- 일반 보스 8종: 공매도 전면 금지 / 빅스텝(이자 ×3) / 상장폐지 심사(고베타 1종목 거래정지) / 증거금 상향(S7의 담보비율 기준 상향) / 금감원 특별 단속(게이지 ×2) / 찌라시 폭탄 / 거래세 인상(매도 1%) / 개미 털기(갭 ×2, 시그널 적중 −15%p). 최종 보스 2종: 블랙 먼데이 / 버블의 정점.
- **S1 이후라 보스 효과를 정산에도 걸 수 있다**: 예) "정산 배수 상한 ×100 주간", "더하기 유물 무효 주간" — 곱하기 빌드의 카운터. 2~3개를 일반 보스 풀에 추가 제안 🛑.
- 보스 격파 보상: 유물 선택지 +1, 비자금 `BOSS_SLUSH_BONUS`. 도감 "보스" 탭, 파산 기록에 사인 표시.
- 시뮬: 보스별 생존율, 전략별 가장 치명적인 보스. 모든 전략 생존 90%↑ = 약함, 20%↓ = 강함 보고. 문서 `BOSS_WEEKS.md`.

### S10. 메타 진행

- **(35) 카드·유물 해금**: 처음엔 일부만 보상 풀에. 조건 달성 시 해금 + 타이틀/결산에 "NEW!" 연출. 해금 조건 예: 반대매매 3회 → 반대매매 불사조, 한 판에 조 단위 → 무량대수. 조건 목록 🛑 사용자 확인. localStorage `hodl.unlocks`.
- **(36) 해금 트리 화면**: 캐릭터별 가지 모양으로 노드 표시(잠금·해금·조건). 시각적으로는 테크트리, 실제로는 콘텐츠 해금.
- **(37) 시작 캐릭터**: 주린이(기본) / 코인러(🔥, 코인 종목 반대매매 기준 완화) / 가치투자자(💎, 3일 이상 보유 이자 면제) / 공매도 세력(📉, 대차 이자 절반) / 리딩방 방장(🎰🕴, 찌라시 하루 +1). 해금 조건 = 그 빌드를 경험하게 하는 도전.
- **(38) 난이도 등급(증권사 등급 1~8)**: 8주 클리어마다 다음 등급, 등급마다 규칙 하나 추가(시작 자금↓, 이자↑, 보스 강화 등).
- **(39) 첫 판 보정**: 첫 판(`hodl.antRuns === 0`) 첫 주는 희귀 이상 카드·곱하기 유물 확률 상향 → 첫날부터 불타는 정산을 한 번은 보게.
- **(40) 원칙 기록**: 영구 능력치 강화(시작 자금 +10% 영구 등)는 **넣지 않는다**. 해금은 선택지를 넓힐 뿐 강하게 만들지 않는다. `CLAUDE.md`에 원칙으로 추가.
- **(8) 무한 모드**: 8주 클리어 후 "계속하기" → 목표가 주마다 ×10(`ENDLESS_TARGET_MULT`). 기록 = 도달 최고 금액·생존 주차. 조·경·해·자는 여기서. 본편 8주 밸런스는 건드리지 않는다.
